## Context

参见 `proposal.md`。插件的立身约束是不调用外部视频生成 API、不读取 API key、不联网，因此"视觉判定"不能由插件自己执行——它没有也不应拥有模型调用能力。同时宿主 agent 本身具备视觉输入能力，且流水线已经在等它（`src/integrations/reelbench-adapter.mjs` 的 `runAnalyzeEvidence` 返回 `AWAITING_CODEX_ANNOTATION`）。既有约束：不改 `run`/`accept` 状态机，不破坏"模型建议不能覆盖确定性失败"与"人工驳回不能被模型分数覆盖"两条已发布规则。

## Goals / Non-Goals

**Goals:**

- 让 `semanticConsistency` 成为有真实生产者、可审计、可跨轮比较的门。
- 在补齐该门的同时保持插件"零模型调用、零外部 API、零网络"的纯度。
- 复用既有物证管道，不新建一套抽帧或联系表实现。

**Non-Goals:**

- 不让插件自己看图，也不让插件调用任何视觉模型。
- 不让视觉分参与硬门判定，也不让它自动推进作业状态。
- 不在本变更中实现跨轮回归检测与停滞升级（由 `2026-09-21-add-revision-loop-discipline` 交付）。
- 不替代版权、品牌、无障碍或人工播放判断——沿用 judge 技能既有的能力边界声明。
- 不移植 dream-loop 的自循环与模型分层路由。

## Decisions

1. **评分由宿主 agent 产出，插件只负责"给足物证 + 定义 rubric + 校验回填"。** 曾考虑让插件内嵌一个视觉模型调用，被否决：那会直接违反插件已发布的"不调用外部视频 API、不读取 API key"承诺，并引入凭据管理面。把"看"留给宿主、把"结构与证据校验"留给插件，是唯一能同时满足两边约束的形态。

2. **回填走受 schema 约束的文件而非 stdin 或环境变量。** 评分因此成为可归档、可哈希、可在台账中引用的产物；同时避免把大段 JSON 塞进 argv。环境变量方案被否决，因为凭据与数据不得经由环境传递是本仓既有纪律。

3. **物证包必须包含目标图与成片帧的同尺度配对。** dream-loop 的核心纪律是逐像素对齐目标，因此只给成片帧是不够的——评分者必须同时看到目标与现状才能形成有意义的差距判断。复用 `video-shots` 的联系表能力，不新增实现。

4. **rubric 移植自 dream-loop 但剥离与视频无关的分支。** 四维（构图 / 光照 / 材质 / 细节）与 0-3-3-3-1 权重对视频帧同样成立；dream-loop 中面向 3D 场景与引擎帧率的分支（如 "target FPS acceptable"）、以及 Plus 模式对 Blender 的否定性结论均不移植——后者与本生态 blender-design 插件定位冲突，应由素材获取决策独立裁定。

5. **该门永远是 advisory，且这一点被硬编码进判定合成。** 保持既有形态：硬门失败直接 `fail`；该门为 `FAIL` 只把判定上限压到 `review`，既不能把 `fail` 抬成 `review`，也不能阻止人工批准。理由：视觉分是模型产出，而插件明令"模型建议不能覆盖确定性失败"。

6. **目标图缺失或无评分时该门为 `NOT_RUN`，不是 `FAIL`。** 沿用四态语义：没有基准不等于不达标。这也保证未使用该能力的既有用户行为完全不变。

7. **评分必须证据绑定。** 回填的每条缺口必须引用物证包中实际存在的帧标识，插件校验该引用。这是防止"不看物证直接编造评分"的主要技术手段。

## Risks / Trade-offs

- [宿主 agent 可能不看物证就编造评分] → 强制证据绑定：引用物证包外的帧即拒绝回填；物证包写入可哈希清单，台账记录评分文件摘要。
- [模型自评倾向抬高分数] → 本变更只保证门存在、可审计、证据绑定；防自评收敛依赖独立上下文与跨轮回归检测，明确移交 `2026-09-21-add-revision-loop-discipline`。
- [物证包体积膨胀宿主上下文] → 默认只产出联系表级别的配对（一张表覆盖多镜头），仅在评分者明确要求单镜头时才产出单帧；沿用 `video-shots` 的"先看联系表，再看单帧"策略。
- [移植 dream-loop 文本涉及 MIT 归属] → 不逐字拷贝其文档，rubric 改写后写入本仓，并在受影响文件与 `THIRD_PARTY_NOTICES.md` 中保留方法来源说明（dream-loop, Anshu Chimala, MIT）。
- [评分者与实现者同一上下文导致分数趋同] → 技能层要求独立上下文评分；插件层不强制（无法验证宿主上下文），但跨轮回归检测会在分数虚高时暴露停滞。
- [目标图本身质量差导致"精确对齐错误目标"] → 目标图必须是"精确写实的目标截图"而非概念图；该纪律写入 plan 技能，并要求用户可替换目标图重新判定。

## Migration Plan

1. 落地 schema 与物证产出路径。`--target` 为可选参数，未提供时该门 `NOT_RUN`，行为与现状完全一致。
2. 接入评分回填与判定合成，硬编码 advisory 边界。
3. 更新 judge / harness / plan 技能文档，补入 rubric 与执行顺序。
4. 补测试：有目标图且有评分、有目标图无评分、无目标图、评分引用无效证据四种情形。
5. bump minor 版本，同步插件仓与市场仓，并更新 `THIRD_PARTY_NOTICES.md`。
